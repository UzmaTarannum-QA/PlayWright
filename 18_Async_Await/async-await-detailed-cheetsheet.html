Playwright Async JavaScript - SDET Revision Guide

1. Callback

Foundation

Definition: A function passed to another function, executed after a task completes.

Why it was introduced?
JavaScript cannot wait for long-running tasks like API calls, file reads or timers. Callbacks provided a way to continue execution after completion.

Example:

setTimeout(() => {
   console.log("Done");
}, 2000);

Pros: Simple for small tasks.

Cons: Callback Hell, difficult debugging, nested code.

Interview Line:
Promises were introduced primarily to solve Callback Hell.

Playwright:
Rarely used directly because Playwright APIs return Promises.

2. Promise

Modern Async Foundation

Definition: An object representing the eventual success or failure of an asynchronous operation.

States:

Pending
Resolved (Fulfilled)
Rejected

Creating a Promise:

const p = new Promise((resolve,reject)=>{
   resolve("Success");
});

Consume:

p.then()
 .catch();

Pros: Cleaner than callbacks.

Cons: Long promise chains reduce readability.

Playwright Reality:
Every major Playwright action returns a Promise. 

page.goto()
page.click()
page.fill()
page.waitForURL()

Interview Line:
Playwright is Promise-based.

3. async

Promise Wrapper

Definition: Marks a function as asynchronous.

Important Rule:

async function test(){
   return "Hello";
}
Actually returns: 
Promise.resolve("Hello")

Pros: Cleaner asynchronous programming.

Cons: Beginners often forget that async always returns a Promise.

Playwright Example:

async function login(page){
   // automation steps
}

Interview Line:
Every function that uses await must be marked async.

4. await

Wait for Promise

Definition: Pauses the current async function until the Promise settles.

Without await:

page.click();
page.fill();

May execute out of order.

With await:

await page.click();
await page.fill();

Pros: Readable, clean, sequential flow.

Cons: Too many awaits can slow tests when actions are independent.

Playwright Rule:
If a Playwright API returns a Promise, use await unless intentionally running in parallel.

Interview Line:
await does not block JavaScript, it only pauses the current async function.

5. Promise.all()

Parallel Execution

Definition: Starts multiple Promises together and waits for all of them.

Why Important?

await task1();
await task2();
await task3();
Time: 
2 + 2 + 2 = 6 sec
vs 
await Promise.all([
   task1(),
   task2(),
   task3()
]);
Time: 
~2 sec

Pros: Faster execution.

Cons: One failure fails the entire Promise.all.

Most Important Playwright Usage:

await Promise.all([
   page.waitForNavigation(),
   page.click("#login")
]);

Why?
Navigation listener starts before click triggers navigation.

Interview Line:
Promise.all is used when tasks are independent.

6. Promise.race()

First Winner Wins

Definition: Returns the result of the first Promise that completes.

Example:

await Promise.race([
   slowTask(),
   fastTask()
]);

Result comes from fastTask().

Pros: Useful for timeout handling.

Cons: Remaining Promises still continue in background.

Playwright Style Usage:

await Promise.race([
   apiCall(),
   timeoutPromise()
]);

Interview Line:
Promise.race waits for the first settled Promise, not all Promises.

🔥 Playwright Interview Flow

Callback
   ↓
Promise
   ↓
async
   ↓
await
   ↓
Promise.all
   ↓
Promise.race

Remember:

Callback      = Run this later

Promise       = Future result

async         = Function returns Promise

await         = Wait for Promise result

Promise.all   = Run all, wait all

Promise.race  = Run all, take first result

💡 What a Good SDET Knows

1. Every Playwright API returns Promise.

2. Most Playwright code is:
   async + await

3. Promise.all improves execution speed.

4. Promise.race helps build timeouts.

5. Avoid unnecessary sequential awaits.

6. Know WHY await is needed,
   not just WHERE to put it.
